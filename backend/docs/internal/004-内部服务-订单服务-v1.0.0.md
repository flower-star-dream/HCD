# 内部服务-订单服务需求文档

## 1. 服务概述

订单服务是HCD项目的核心服务之一，主要负责订单的创建、查询、更新、取消等功能。该服务为其他业务模块提供内部API接口，支持订单信息查询、订单状态更新、订单退款等操作。

## 2. 技术规范

### 2.1 代码架构

订单服务采用分层架构设计，包含以下模块：

- **order-ao**：数据传输对象（DTO），定义服务间数据传输格式
- **order-api**：API接口层，定义对外暴露的接口
- **order-biz**：业务逻辑层，实现核心业务逻辑
- **order-bo**：业务对象层，定义数据库实体
- **order-constant**：常量定义层，定义服务常量
- **order-boot**：服务启动层，负责服务初始化和启动

### 2.2 数据库设计

订单服务使用以下数据库表，所有表均包含5个通用审计字段：

| 字段名       | 数据类型 | 描述               | 约束 |
|------------|---------|-------------------|------|
| id         | BIGINT  | 主键ID             | 自增 |
| createTime | DATETIME| 创建时间           | NOT NULL |
| updateTime | DATETIME| 更新时间           | NOT NULL |
| createPerson | BIGINT | 创建人ID           | NOT NULL |
| updatePerson | BIGINT | 更新人ID           | NOT NULL |

**核心表结构**：

- **order**：订单表，存储订单基本信息
- **order_item**：订单项表，存储订单商品详情

### 2.3 响应格式

所有API接口均使用统一的响应格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 2.4 依赖关系

- **hcd-base**：基础组件库，提供通用工具类和基础服务
- **hcd-tools**：工具组件库，提供结果封装、异常处理等功能
- **MyBatis Plus**：ORM框架，简化数据库操作
- **Spring Cloud**：微服务框架，提供服务注册与发现、负载均衡等功能

## 3. 功能需求

### 3.1 订单信息查询
- 支持根据用户ID查询订单列表
- 支持根据订单ID查询订单详情
- 支持查询订单状态

### 3.2 订单状态更新
- 支持更新订单总价
- 支持订单退款
- 支持更新订单状态

### 3.3 订单管理
- 支持创建订单
- 支持取消订单
- 支持订单支付

## 4. API接口

### 4.1 根据用户ID获取订单ID列表

**接口地址**：`/api/v1/internal/order/order/by-user`

**请求方式**：GET

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| userId | Long | 用户ID | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": [1, 2, 3]
}
```

### 4.2 更新订单总价

**接口地址**：`/api/v1/internal/order/order/totalPrice`

**请求方式**：PUT

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| orderId | Long | 订单ID | 必传 |
| newTotalPrice | BigDecimal | 新的总价 | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

### 4.3 订单退款

**接口地址**：`/api/v1/internal/order/order/refund`

**请求方式**：PUT

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| orderId | Long | 订单ID | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

### 4.4 获取订单状态

**接口地址**：`/api/v1/internal/order/order/status`

**请求方式**：GET

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| orderId | Long | 订单ID | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": 1
}
```

## 5. 依赖服务

- **用户服务**：获取用户信息
- **票务服务**：获取票务信息
- **列车座位服务**：获取座位信息

## 6. 数据安全

- 所有内部API接口均通过Spring Cloud Gateway进行访问控制
- 使用JWT令牌进行身份认证和授权
- 接口调用采用HTTPS协议，确保数据传输安全
- 敏感数据采用加密存储

## 7. 监控与日志

- 服务集成Prometheus和Grafana，实现指标监控
- 使用ELK进行日志收集和分析
- 关键操作记录审计日志
- 服务健康检查和熔断机制

## 8. 部署与扩展

- 服务支持容器化部署，使用Docker和Kubernetes
- 支持水平扩展，根据业务需求动态调整实例数量
- 服务注册与发现使用Nacos
- 配置中心使用Nacos
