# 内部服务-列车座位服务需求文档

## 1. 服务概述

列车座位服务是HCD项目的核心服务之一，主要负责列车座位的管理、分配、查询等功能。该服务为其他业务模块提供内部API接口，支持座位信息查询、座位状态更新、座位分配等操作。

## 2. 技术规范

### 2.1 代码架构

列车座位服务采用分层架构设计，包含以下模块：

- **trainSeat-ao**：数据传输对象（DTO），定义服务间数据传输格式
- **trainSeat-api**：API接口层，定义对外暴露的接口
- **trainSeat-biz**：业务逻辑层，实现核心业务逻辑
- **trainSeat-bo**：业务对象层，定义数据库实体
- **trainSeat-constant**：常量定义层，定义服务常量
- **trainSeat-boot**：服务启动层，负责服务初始化和启动

### 2.2 数据库设计

列车座位服务使用以下数据库表，所有表均包含5个通用审计字段：

| 字段名       | 数据类型 | 描述               | 约束 |
|------------|---------|-------------------|------|
| id         | BIGINT  | 主键ID             | 自增 |
| createTime | DATETIME| 创建时间           | NOT NULL |
| updateTime | DATETIME| 更新时间           | NOT NULL |
| createPerson | BIGINT | 创建人ID           | NOT NULL |
| updatePerson | BIGINT | 更新人ID           | NOT NULL |

**核心表结构**：

- **train_seat**：列车座位表，存储列车座位基本信息
- **train_seat_status**：列车座位状态表，存储座位状态变更记录

### 2.3 响应格式

所有API接口均使用统一的响应格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 2.4 依赖关系

- **hcd-base**：基础组件库，提供通用工具类和基础服务
- **hcd-tools**：工具组件库，提供结果封装、异常处理等功能
- **MyBatis Plus**：ORM框架，简化数据库操作
- **Spring Cloud**：微服务框架，提供服务注册与发现、负载均衡等功能

## 3. 功能需求

### 3.1 座位信息查询
- 支持根据列车ID、车厢号、座位号查询座位信息
- 支持批量查询座位信息
- 支持查询座位状态

### 3.2 座位状态更新
- 支持更新座位状态（可用、已售、已预订、已锁定）
- 支持批量更新座位状态

### 3.3 座位分配
- 支持根据订单信息分配座位
- 支持自动分配座位
- 支持手动分配座位

## 4. API接口

### 4.1 座位信息查询接口

**接口地址**：`/api/v1/internal/trainSeat/seat/info`

**请求方式**：POST

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| seatIds | List<Long> | 座位ID列表 | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "trainId": 1001,
      "carriageNumber": "1",
      "seatNumber": "1A",
      "seatType": "硬座",
      "status": 0,
      "createTime": "2025-11-21 14:07:00",
      "updateTime": "2025-11-21 14:07:00",
      "createPerson": 1,
      "updatePerson": 1
    }
  ]
}
```

### 4.2 座位状态更新接口

**接口地址**：`/api/v1/internal/trainSeat/seat/updateStatus`

**请求方式**：PUT

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| seatIds | List<Long> | 座位ID列表 | 必传 |
| status | Integer | 座位状态 | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

### 4.3 座位分配接口

**接口地址**：`/api/v1/internal/trainSeat/seat/allocate`

**请求方式**：POST

**请求参数**：

| 参数名 | 数据类型 | 描述 | 约束 |
|--------|---------|------|------|
| orderId | Long | 订单ID | 必传 |
| trainId | Long | 列车ID | 必传 |
| carriageNumber | String | 车厢号 | 可选 |
| seatCount | Integer | 座位数量 | 必传 |

**响应数据**：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "trainId": 1001,
      "carriageNumber": "1",
      "seatNumber": "1A",
      "seatType": "硬座"
    }
  ]
}
```

## 5. 依赖服务

- **用户服务**：获取用户信息
- **票务服务**：获取票务信息
- **订单服务**：获取订单信息

## 6. 数据安全

- 所有内部API接口均通过Spring Cloud Gateway进行访问控制
- 使用JWT令牌进行身份认证和授权
- 接口调用采用HTTPS协议，确保数据传输安全
- 敏感数据采用加密存储

## 7. 监控与日志

- 服务集成Prometheus和Grafana，实现指标监控
- 使用ELK进行日志收集和分析
- 关键操作记录审计日志
- 服务健康检查和熔断机制

## 8. 部署与扩展

- 服务支持容器化部署，使用Docker和Kubernetes
- 支持水平扩展，根据业务需求动态调整实例数量
- 服务注册与发现使用Nacos
- 配置中心使用Nacos
