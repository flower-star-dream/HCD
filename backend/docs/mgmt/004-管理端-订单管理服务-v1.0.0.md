# 管理端-订单管理服务需求文档 v1.0.0

## 1. 服务概述

管理端订单管理服务为火车订票系统后台管理端提供订单相关的管理功能，包括订单查询、订单状态管理、订单详情查看等完整的订单运营管理功能。

## 2. 技术规范

### 2.1 核心技术栈

- **编程语言**: Java 17
- **框架**: Spring Boot 3.2.7
- **微服务**: Spring Cloud 2023.0.0
- **服务治理**: Spring Cloud Alibaba 2023.0.0.0-RC1
- **数据库**: MySQL 8.0.33
- **ORM框架**: MyBatis Plus 3.5.5
- **缓存**: Redis

### 2.2 架构设计

```
order-parent/
├── order-ao/                # 应用对象（DTO）
├── order-api/               # API接口和Feign客户端
├── order-biz/               # 业务逻辑实现
├── order-bo/                # 业务对象（实体）
├── order-constant/          # 常量定义
└── order-boot/              # 服务启动模块
```

### 2.3 数据库设计

所有数据库表必须继承BaseEO类，包含以下5个通用审计字段：
- `id`: 主键ID（Long类型，使用MyBatis Plus的IdType.ASSIGN_ID）
- `createTime`: 创建时间（LocalDateTime类型）
- `updateTime`: 更新时间（LocalDateTime类型）
- `createPerson`: 创建人（String类型）
- `updatePerson`: 更新者（String类型）

#### 2.3.1 订单表（hcd_order）

| 字段名 | 数据类型 | 描述 |
|-------|---------|------|
| id | bigint | 订单编号（主键，MyBatis Plus自动生成） |
| user_id | bigint | 订购用户id |
| status | int | 订单支付状态 |
| remarks | varchar(100) | 订单备注 |
| total_price | decimal(10,2) | 总价 |
| amount_paid | decimal(10,2) | 已付金额 |
| pay_time | datetime | 支付时间 |
| create_time | datetime | 创建时间（MyBatis Plus自动填充） |
| update_time | datetime | 更新时间（MyBatis Plus自动填充） |
| create_person | varchar(30) | 创建人（MyBatis Plus自动填充） |
| update_person | varchar(30) | 更新者（MyBatis Plus自动填充） |

## 3. 功能需求

### 3.1 订单查询管理

#### 3.1.1 分页查询订单列表

- **功能描述**: 分页查询所有订单信息，支持多种筛选条件
- **输入参数**: 页码、每页条数、订单状态、时间范围、用户关键词、订单号、金额范围等
- **输出结果**: 订单信息列表
- **业务规则**: 
  - 支持按订单状态筛选
  - 支持按时间范围查询
  - 支持按用户信息搜索
  - 支持按订单金额范围筛选
  - 分页返回结果
  - 需要管理员权限

#### 3.1.2 查询订单详情

- **功能描述**: 查询指定订单的详细信息，包含完整的车票和乘车人信息
- **输入参数**: 订单ID
- **输出结果**: 订单详细信息
- **业务规则**: 
  - 查询订单基础信息
  - 查询关联的用户信息
  - 查询关联的所有车票详情
  - 查询每张车票对应的乘车人信息
  - 计算订单的支付状态和时间信息

### 3.2 订单状态管理

#### 3.2.1 修改订单状态

- **功能描述**: 修改订单的状态，用于订单的特殊处理
- **输入参数**: 订单ID、目标状态、状态变更原因、备注说明等
- **输出结果**: 操作结果
- **业务规则**: 
  - 验证订单存在性
  - 检查目标状态的合法性
  - 记录状态变更原因
  - 更新订单状态
  - 记录操作日志
  - 触发相关的业务处理（如退款、通知等）

#### 3.2.2 取消订单

- **功能描述**: 取消订单
- **输入参数**: 订单ID、用户ID等
- **输出结果**: 取消结果
- **业务规则**: 
  - 只有待支付的订单才能取消
  - 取消订单后更新订单状态为已取消
  - 取消订单后释放关联的座位
  - 取消订单后更新关联的车票状态

## 4. API接口

### 4.1 管理端接口

| 接口路径 | 方法 | 功能描述 | 请求参数 | 响应格式 |
|---------|------|---------|---------|---------|
| /api/v1/mgmt/order/order/page | GET | 分页查询订单列表 | OrderPageQueryREQ | Result<PageResult<OrderMgmtRES>> |
| /api/v1/mgmt/order/order/{id} | GET | 查询订单详情 | orderId | Result<OrderMgmtRES> |
| /api/v1/mgmt/order/order/status | PUT | 更新订单状态 | OrderStatusREQ | Result<Void> |
| /api/v1/mgmt/order/order/cancel | PUT | 取消订单 | orderId, userId | Result<Void> |

## 5. 业务流程

### 5.1 订单列表查询流程

1. 管理端发起订单列表查询请求
2. 调用订单服务的分页查询订单列表接口
3. 订单服务验证管理员权限
4. 验证通过后，根据查询条件查询订单列表
5. 返回订单列表给管理端

### 5.2 订单详情查询流程

1. 管理端发起订单详情查询请求
2. 调用订单服务的查询订单详情接口
3. 订单服务验证管理员权限
4. 验证通过后，查询订单详情信息
5. 查询关联的用户信息、车票信息和乘车人信息
6. 返回订单详情给管理端

### 5.3 订单状态更新流程

1. 管理端发起订单状态更新请求
2. 调用订单服务的更新订单状态接口
3. 订单服务验证管理员权限
4. 验证订单存在性和状态合法性
5. 更新订单状态
6. 记录操作日志
7. 触发相关业务处理
8. 返回更新结果给管理端

## 6. 依赖关系

- **依赖服务**: 票务服务、用户服务、列车座位服务
- **被依赖服务**: 无

## 7. 数据安全

- 所有接口调用需经过认证授权
- 只有管理员可以访问管理端接口
- 敏感数据传输采用HTTPS
- 接口调用频率限制
- 敏感信息需要脱敏显示

## 8. 监控与日志

- 记录关键业务操作日志
- 监控接口调用成功率和响应时间
- 实现服务健康检查
- 订单状态变更操作需要记录操作日志
- 异常订单处理操作需要记录操作日志

## 9. 部署与运维

- 采用Docker容器化部署
- 支持水平扩展
- 提供/health端点用于健康检查
