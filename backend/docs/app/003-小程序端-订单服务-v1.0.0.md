# 小程序端-订单服务需求文档 v1.0.0

## 1. 服务概述

订单服务是HCD系统的核心服务之一，主要负责管理订单信息，包括订单创建、查询、支付、取消等功能，为用户提供完整的订单生命周期管理。

## 2. 技术规范

### 2.1 核心技术栈

- **编程语言**: Java 17
- **框架**: Spring Boot 3.2.7
- **微服务**: Spring Cloud 2023.0.0
- **服务治理**: Spring Cloud Alibaba 2023.0.0.0-RC1
- **数据库**: MySQL 8.0.33
- **ORM框架**: MyBatis Plus 3.5.5
- **缓存**: Redis
- **消息队列**: RocketMQ 5.3.2
- **分布式事务**: Seata 2.5.0

### 2.2 架构设计

```
order-parent/
├── order-ao/                # 应用对象（DTO）
├── order-api/               # API接口和Feign客户端
├── order-biz/               # 业务逻辑实现
├── order-bo/                # 业务对象（实体）
├── order-constant/          # 常量定义
└── order-boot/              # 服务启动模块
```

### 2.3 数据库设计

所有数据库表必须继承BaseEO类，包含以下5个通用审计字段：
- `id`: 主键ID（Long类型，使用MyBatis Plus的IdType.ASSIGN_ID）
- `createTime`: 创建时间（LocalDateTime类型）
- `updateTime`: 更新时间（LocalDateTime类型）
- `createPerson`: 创建人（String类型）
- `updatePerson`: 更新者（String类型）

#### 2.3.1 订单表（hcd_order）

| 字段名 | 数据类型 | 描述 |
|-------|---------|------|
| id | bigint | 订单编号（主键，MyBatis Plus自动生成） |
| user_id | bigint | 订购用户id |
| status | int | 订单支付状态 |
| remarks | varchar(100) | 订单备注 |
| total_price | decimal(10,2) | 总价 |
| pay_time | datetime | 支付时间 |
| amount_paid | decimal(10,2) | 已付金额 |
| create_time | datetime | 创建时间（MyBatis Plus自动填充） |
| update_time | datetime | 更新时间（MyBatis Plus自动填充） |
| create_person | varchar(30) | 创建人（MyBatis Plus自动填充） |
| update_person | varchar(30) | 更新者（MyBatis Plus自动填充） |

## 3. 功能需求

### 3.1 订单创建功能

- **功能描述**: 创建订单信息
- **输入参数**: 用户ID、车票信息列表、总价等
- **输出结果**: 创建的订单信息
- **业务规则**: 
  - 订单创建时必须关联用户
  - 订单创建时必须关联车票
  - 订单状态初始化为待支付
  - 订单创建后生成唯一订单编号

### 3.2 订单查询功能

- **功能描述**: 查询订单信息
- **输入参数**: 订单ID、用户ID、状态等
- **输出结果**: 订单信息列表
- **业务规则**: 
  - 支持按多种条件查询订单
  - 支持分页查询
  - 用户只能查询自己的订单

### 3.3 订单支付功能

- **功能描述**: 支付订单
- **输入参数**: 订单ID、支付金额等
- **输出结果**: 支付结果
- **业务规则**: 
  - 只有待支付的订单才能支付
  - 支付金额必须等于订单总价
  - 支付成功后更新订单状态为已支付
  - 支付成功后更新支付时间和已付金额

### 3.4 订单取消功能

- **功能描述**: 取消订单
- **输入参数**: 订单ID、用户ID等
- **输出结果**: 取消结果
- **业务规则**: 
  - 只有待支付的订单才能取消
  - 取消订单后更新订单状态为已取消
  - 取消订单后释放关联的座位
  - 取消订单后更新关联的车票状态

### 3.5 订单退款功能

- **功能描述**: 订单退款
- **输入参数**: 订单ID等
- **输出结果**: 退款结果
- **业务规则**: 
  - 只有已支付的订单才能退款
  - 退款成功后更新订单状态为已退款
  - 退款成功后调用支付网关进行退款
  - 退款成功后更新关联的车票状态

## 4. API接口

### 4.1 小程序端接口

| 接口路径 | 方法 | 功能描述 | 请求参数 | 响应格式 |
|---------|------|---------|---------|---------|
| /api/v1/app/order/create | POST | 创建订单 | OrderREQ | Result<Void> |
| /api/v1/app/order/list | GET | 获取订单列表 | userId | Result<List<OrderRES>> |
| /api/v1/app/order/detail | GET | 获取订单详情 | orderId | Result<OrderMgmtRES> |
| /api/v1/app/order/pay | POST | 支付订单 | OrdersPaymentREQ | Result<OrderPaymentRES> |
| /api/v1/app/order/cancel | POST | 取消订单 | orderId, userId | Result<Void> |

## 5. 业务流程

### 5.1 订单创建流程

1. 小程序端选择车票并提交订单
2. 调用订单服务的创建订单接口
3. 订单服务验证用户信息和车票信息
4. 验证通过后，生成订单记录
5. 调用票务服务创建车票信息
6. 返回订单信息给小程序端

### 5.2 订单支付流程

1. 小程序端发起支付请求
2. 调用订单服务的支付订单接口
3. 订单服务验证订单状态和支付金额
4. 验证通过后，调用支付网关进行支付
5. 支付成功后，更新订单状态为已支付
6. 更新订单的支付时间和已付金额
7. 返回支付结果给小程序端

### 5.3 订单取消流程

1. 小程序端发起取消订单请求
2. 调用订单服务的取消订单接口
3. 订单服务验证订单状态
4. 验证通过后，更新订单状态为已取消
5. 调用票务服务更新车票状态为已取消
6. 调用列车座位服务释放关联的座位
7. 返回取消结果给小程序端

### 5.4 订单退款流程

1. 小程序端发起退款请求
2. 调用订单服务的订单退款接口
3. 订单服务验证订单状态
4. 验证通过后，调用支付网关进行退款
5. 退款成功后，更新订单状态为已退款
6. 调用票务服务更新车票状态为已退款
7. 返回退款结果给小程序端

## 6. 依赖关系
